# Saltline (cod)

A browser multiplayer FPS, live at https://cod.rabeeta.xyz. The game was built as a claude.ai artifact; this repo runs it on Cloudflare instead.

## Stack

Everything runs on Cloudflare. There is no other server, database or build tool.

| Layer | Cloudflare product | Where | What it does |
|---|---|---|---|
| Static files | Workers Static Assets | `web/` | Serves `index.html` (the game) and `net.js` from the edge; `net.js` loads `touch.js`, the layout editor for the touch buttons (Settings, Touch controls), which keeps each player's layout in their browser, `fragpath.js`, the path of a cooked grenade, and `fullmap.js`, the whole map in the top right corner of the pause screen (drawn from the walk grid, like the minimap; it shows no more than the minimap does). `/r/<code>` invite links fall back to `index.html` (SPA mode) |
| API | Workers | `src/worker.js` | Only `/api/*` runs code (`run_worker_first` in `wrangler.jsonc`) |
| Rooms | Durable Objects (SQLite-backed), class `Room` | `src/worker.js` | One per 6-char room code. Holds up to 10 WebSockets (hibernation API), relays player state and WebRTC signalling |
| Matchmaking | Durable Objects, class `Matchmaker` | `src/worker.js` | One per continent (from `request.cf`), map and mode (Deathmatch or Team deathmatch). Fills the fullest open public room first |
| Player counts | Durable Objects, class `Census` | `src/worker.js` `/api/online` | One global instance. Every room reports its count on join/leave; quiet rooms are re-checked so a crashed room can't leave a stale number. Feeds the global numbers on the first screen. The in-match "N in this match" line doesn't use it: `net.js` counts that live from the room connection |
| Maps | Workers Static Assets | `web/maps.js`, `web/maps/` | The game builds one map per page load. `maps.js` picks it before the game starts (`?map=`, the room's map, or the player's last pick); `maps/colosseum.js` builds the Colosseum `maps/alpine.js` the Alpine village (its textures and sky photograph are in `maps/alpine/`) and `maps/maram.js` the Maram desert town (its model, collision and sunrise photograph are in `maps/maram/`). Rooms store their map and the mode they open on; quick play has one `Matchmaker` per continent, map and mode. The menu's map cards are pictures from above, `maps/cards/<id>.jpg` (800 x 450, one per map) |
| Voice | Realtime STUN/TURN | `src/worker.js` `/api/ice` | Free STUN by default; TURN when the `TURN_KEY_ID` / `TURN_KEY_API_TOKEN` secrets are set. Audio itself is peer-to-peer WebRTC |
| Domain | Workers Custom Domain | `wrangler.jsonc` `routes` | `cod.rabeeta.xyz` on the `rabeeta.xyz` zone. `workers.dev` and preview URLs are off |
| Logs | Workers Observability | `wrangler.jsonc` | On |
| CI/CD | Workers Builds | Cloudflare dashboard | Every push to `master` runs `npx wrangler deploy`. No build command |

Front end is plain JS: the game is a single minified HTML file (three.js bundled inside), and `web/net.js` stands in for the claude.ai runtime (`window.claude.use(...)`) that the game was written against. Wrangler is the only dependency.

## Rules that are not obvious from the code

- **The menus around the matches are `web/net.js`, not the game.** Home, Quick play, Private match and the room lobby are drawn there, over the game's own title screen (their Settings button opens the game's own settings panel), and start matches by pressing the game's own (hidden) join buttons, so the game's checks still run. Changing a map reloads the page, so a map card only marks the choice; the reload comes with Find match or with entering a room. A new map needs its card picture too.

- **`web/index.html` is generated.** `npm run import [path]` turns a raw claude.ai export (`COD.html`, gitignored) into it, removing the author's note, work references and a 1.9 MB legacy build. Change the game by re-exporting and re-importing. Each patch in `scripts/import.mjs` fails loudly when its anchor moves; fix the anchor, never loosen the check. The final check refuses any output that still names the original author or employer.
- **A map is three things.** A file in `web/maps/` that registers itself in `window.__SALTLINE_MAPS`, its script tag in `scripts/map-hooks.mjs`, and its id in `MAPS` in `src/worker.js` (the server only stores maps it knows). The hooks in `map-hooks.mjs` are the only edits to the game for maps: each finds its place by a pattern and fails loudly if it does not match exactly once. A map must not reach into the game beyond those hooks and `window.__G`.
- **Check a map in a browser before pushing.** `npm test` only covers the server. Load `http://localhost:8787/?map=colosseum`, enter a match, and watch the console: the game logs anything that throws.
- **A gun is three things.** Its model, prepared once by `scripts/gun-assets.mjs` into `web/guns/`; its numbers, handling, reload and sounds in `web/guns.js`; and the hooks in `scripts/gun-hooks.mjs`, which are the only edits to the game for guns and for the respawn (four seconds down, five protected). The rifle and pistol are the game's own and stay in the generated file. What goes over the wire keeps its old meaning (shot code 0 rifle, 1 pistol; hit kinds 1 knife, 2 frag; carried 2 knife); new guns take the next numbers, so an old client still plays against a new one.
- **Performance changes to the game go in `scripts/perf-hooks.mjs`** (and `web/perf.js` for the warm-up they call). They are the only edits to the game for speed: the quality presets, the mirror pass, the render size, the warm-up, the starting quality by graphics card. Measure before and after with the same camera and window size; the browser's GPU timer queries are not reliable on Macs, so time whole frames instead. A map switches off what it does not use from its own file: Alpine turns off the rain, the thunder and the mirrored reflection pass (`ground.planar.enabled`).
- **On Alpine, nothing over 3.15 m can be stood on.** Every top that high with open sky over it (a ruined wall, a garden wall's coping, a post, a wall's head under a roof that stops shots only) is carried up to 12 m by a box for players only, made at the end of the map's build, square by square (25 cm), so a top only partly covered is capped where it is open; a square with something over it within 2.6 m (a window sill, a floor under a ceiling) is left alone. Standable things below it: the ground, the blocks and crates (1.35 to 1.95 m), the upstairs floors and the veranda (3.0 m). Roofs stop shots only, so a gap in the caps is a way into a sealed house. After any change to its buildings, run a walk-jump-and-vault check over the whole map before pushing.
- **Maram's collision is generated.** `web/maps/maram/world.json` comes from `node scripts/maram-build.mjs` (pass a `.glb` to take in a new model); never edit it by hand. The build fails if a spawn, an ammo pile or the intro camera path is wrong, and prints what its walk-and-jump robot reached. The map replaces the game's raycast, moveCapsule and groundHeight with the same code over a grid (it has about 40,000 boxes) and checks them against the game's own on load; after a new game export, watch the console for `[maram] the grid physics disagreed`.
- **The game reads `volSigma`, `volFarHaze` and `volMaxDist` from `render.tune` only when the renderer starts.** A map that sets them changes nothing (Alpine's `volSigma` never took effect); `volSunScale`, `volAmbient` and the covered-box density (`volInterior…`) are read every frame. That is why Maram draws its own sunbeams. Maram also borrows Alpine's texture folder (`web/maps/alpine/tex/`) for its surface detail: renaming a texture there leaves Maram plain.
- **Move the camera before `G.render.frame`, never in a pre-pass.** The frame copies the camera into the one that draws the gun and arms first, then runs the pre-passes, so a camera moved in a pre-pass leaves the gun behind (Maram's smoothed eye made the gun jump on every stair until it wrapped `G.render.frame` instead).
- **Grenades fly in fixed steps of 1/120 s** (gun hook 24), and `web/fragpath.js` flies the cooked grenade's path through a copy of those steps (`stepFrags`, with hook 22's floor ray): change one and change the other, or the drawn path lies. Measured on Alpine: where the grenade goes off is within 5 cm of the drawn end. A grenade's floor is a ray down, never `groundHeight`, which counts player-only boxes (Alpine's 12 m caps).
- **Deathmatch colours are unique per room.** The rows are in `net.js` (the last block); the colour is the game's (`window.__SALTLINE_COLOR`, import patch 11). On a clash, whoever was in the room first keeps it (`room.earlier(peer)`: the peers already there when this page first joined).
- **Typed radio is gone.** `scripts/import.mjs` (10) takes out the T key, its line, its hint, its key in Controls and the lines sent and read aloud; `net.js` offers no `tts`. Voice chat (V) is untouched. A new export keeps it out only while those anchors still match.
- **Vaulting is `web/vault.js`**, called from hooks in `scripts/gun-hooks.mjs` (17) at the game's jump. It clears tops from 45 cm up to 1.65 m above the feet, under what a jump reaches (1.69 m with the step), or as high as the map's `level.vaultMax` (Alpine: 1.95 m, safe there only because of the caps above). Up to 1.2 m, or across anything thinner than half a metre, it goes over; higher and deeper (a block, a crate) it climbs onto the top. It tries straight ahead and square on to the face, each a little to either side, so a window is found without lining up on it; boxes marked `noVault` are never vaulted (Alpine's bushes had it; they are no longer solid at all). The motion is one curve through a few moments (start, hands, edge, over, out) that keeps the player's speed. It checks the whole path against the boxes near the player first; `__SALTLINE_VAULT.why()` in the console says why the last try was refused, `.last()` how the last vault went, `.test(G, x, y, z, yaw)` what a vault from a spot would do. The body is the soldier rig's own pose with a few extra inputs (a hand on the ledge, knees tucked, hips low, a lean): your hands are the knife's first-person arm (a mirrored copy for the left), the gun dips in the weapon's own holster pose, and other players get `vt` in the presence.
- **A peek is drawn where it is.** Leaning (Q/E) moves the eye up to 50 cm to the side and 20 cm down; the presence carries the offset (`lo`), and other players' games lean the soldier from the hips (`leanK`) so his head is where that eye is, his feet moving at most 25 cm to make up the rest, with the hitboxes following (gun hooks, section 18). Measured: head within 2 cm of the eye, feet about 17 cm. Anything that changes how far the eye leans or how the body tilts must keep the two in step.
- **A reload goes back into the match.** On joining a match `net.js` keeps the room, mode and team in `sessionStorage` (`saltline.resume`, this tab only, fresh for ten minutes) and a reload joins the same room again; going back to the menus or Leave room forgets it.
- **A private room's map can change.** Its lobby sends `{t:'map'}` over the room's socket; the Room stores it and tells everyone, and every page reloads into the new map at `/r/<code>`. Public rooms keep their map, because quick play finds them by map.
- **Check guns with two players.** One browser cannot be shot. Two tabs on `npm run dev`, both in Deathmatch: shoot the other, read the kill feed and the card shown when down, come back, and try **B**.
- **The Worker name stays `cod`.** It was renamed from `saltline` in the dashboard, which carried over the custom domain and Durable Objects (their namespaces are still called `saltline_Room` / `saltline_Matchmaker`). Changing `name` in `wrangler.jsonc` alone makes a new, empty Worker instead; rename in the dashboard first.
- **Durable Object classes change only through a new migration tag** in `wrangler.jsonc` (`v2` today). Never edit or delete an existing tag.
- **`master` is production.** Anything merged there goes live in about a minute. Run `npm test` against `npm run dev` before pushing. It is a protocol smoke test that needs a running server, so CI does not run it.
- **The repo is public.** Secrets go in `wrangler secret put` (runtime) or `.dev.vars` (local, gitignored), never in `wrangler.jsonc`.
