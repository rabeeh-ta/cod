# Saltline (cod)

A browser multiplayer FPS, live at https://cod.rabeeta.xyz. The game was built as a claude.ai artifact; this repo runs it on Cloudflare instead.

## Stack

Everything runs on Cloudflare. There is no other server, database or build tool.

| Layer | Cloudflare product | Where | What it does |
|---|---|---|---|
| Static files | Workers Static Assets | `web/` | Serves `index.html` (the game) and `net.js` from the edge; `net.js` loads `touch.js`, the layout editor for the touch buttons (Settings, Touch controls), which keeps each player's layout in their browser, `fragpath.js`, the path of a cooked grenade, `news.js`, the "what's new" card (shown once on each device after an update, and again from "Latest updates!" beside the name on the home screen; change its `NEWS` and its id for the next release), and `fullmap.js`, the whole map in the top right corner of the pause screen (drawn from the walk grid, like the minimap; it shows no more than the minimap does). `/r/<code>` invite links fall back to `index.html` (SPA mode) |
| API | Workers | `src/worker.js` | Only `/api/*` runs code (`run_worker_first` in `wrangler.jsonc`) |
| Rooms | Durable Objects (SQLite-backed), class `Room` | `src/worker.js` | One per 6-char room code. Holds up to 10 WebSockets (hibernation API), relays player state and WebRTC signalling |
| Matchmaking | Durable Objects, class `Matchmaker` | `src/worker.js` | One per continent (from `request.cf`), map and mode (Deathmatch or Team deathmatch). Fills the fullest open public room first |
| Player counts | Durable Objects, class `Census` | `src/worker.js` `/api/online` | One global instance. Every room reports its count on join/leave; quiet rooms are re-checked so a crashed room can't leave a stale number. Feeds the global numbers on the first screen. The in-match "N in this match" line doesn't use it: `net.js` counts that live from the room connection |
| Maps | Workers Static Assets | `web/maps.js`, `web/maps/` | The game builds one map per page load. `maps.js` picks it before the game starts (`?map=`, the room's map, or the player's last pick); `maps/colosseum.js` builds the Colosseum, `maps/alpine.js` the Alpine village (its textures and sky photograph are in `maps/alpine/`), `maps/maram.js` the Maram desert town (its model, collision and sunrise photograph are in `maps/maram/`) and `maps/area51.js` the Area 51 motor pool (its noon photograph and ground textures are in `maps/area51/`). Rooms store their map and the mode they open on; quick play has one `Matchmaker` per continent, map and mode. The menu's map cards are pictures from above, `maps/cards/<id>.jpg` (800 x 450, one per map) |
| Voice | Realtime STUN/TURN | `src/worker.js` `/api/ice` | Free STUN by default; TURN when the `TURN_KEY_ID` / `TURN_KEY_API_TOKEN` secrets are set. Audio itself is peer-to-peer WebRTC |
| Domain | Workers Custom Domain | `wrangler.jsonc` `routes` | `cod.rabeeta.xyz` on the `rabeeta.xyz` zone. `workers.dev` and preview URLs are off |
| Logs | Workers Observability | `wrangler.jsonc` | On |
| CI/CD | Workers Builds | Cloudflare dashboard | Every push to `master` runs `npx wrangler deploy`. No build command |

Front end is plain JS: the game is a single minified HTML file (three.js bundled inside), and `web/net.js` stands in for the claude.ai runtime (`window.claude.use(...)`) that the game was written against. Wrangler is the only dependency.

## Rules that are not obvious from the code

- **The menus around the matches are `web/net.js`, not the game.** Home, Quick play, Private match and the room lobby are drawn there, over the game's own title screen (their Settings button opens the game's own settings panel), and start matches by pressing the game's own (hidden) join buttons, so the game's checks still run. Changing a map reloads the page, so a map card only marks the choice; the reload comes with Find match or with entering a room. A new map needs its card picture too.

- **`web/index.html` is generated.** `npm run import [path]` turns a raw claude.ai export (`COD.html`, gitignored) into it, removing the author's note, work references and a 1.9 MB legacy build. Change the game by re-exporting and re-importing. Each patch in `scripts/import.mjs` fails loudly when its anchor moves; fix the anchor, never loosen the check. The final check refuses any output that still names the original author or employer.
- **A map is three things.** A file in `web/maps/` that registers itself in `window.__SALTLINE_MAPS`, its script tag in `scripts/map-hooks.mjs`, and its id in `MAPS` in `src/worker.js` (the server only stores maps it knows). The hooks in `map-hooks.mjs` are the only edits to the game for maps: each finds its place by a pattern and fails loudly if it does not match exactly once. A map must not reach into the game beyond those hooks and `window.__G`.
- **Check a map in a browser before pushing.** `npm test` only covers the server. Load `http://localhost:8787/?map=colosseum`, enter a match, and watch the console: the game logs anything that throws.
- **A gun is three things.** Its model, prepared once by `scripts/gun-assets.mjs` into `web/guns/`; its numbers, handling, reload and sounds in `web/guns.js`; and the hooks in `scripts/gun-hooks.mjs`, which are the only edits to the game for guns and for the respawn (four seconds down, five protected). The rifle and pistol are the game's own and stay in the generated file. What goes over the wire keeps its old meaning (shot code 0 rifle, 1 pistol; hit kinds 1 knife, 2 frag; carried 2 knife); new guns take the next numbers, so an old client still plays against a new one.
- **Performance changes to the game go in `scripts/perf-hooks.mjs`** (and `web/perf.js` for the warm-up they call). They are the only edits to the game for speed: the quality presets, the mirror pass, the render size, the warm-up, the starting quality by graphics card. Measure before and after with the same camera and window size; the browser's GPU timer queries are not reliable on Macs, so time whole frames instead. A map switches off what it does not use from its own file: Alpine turns off the rain, the thunder and the mirrored reflection pass (`ground.planar.enabled`).
- **On Alpine, nothing over 3.15 m can be stood on.** Every top that high with open sky over it (a ruined wall, a garden wall's coping, a post, a wall's head under a roof that stops shots only) is carried up to 12 m by a box for players only, made at the end of the map's build, square by square (25 cm), so a top only partly covered is capped where it is open; a square with something over it within 2.6 m (a window sill, a floor under a ceiling) is left alone. Standable things below it: the ground, the blocks and crates (1.35 to 1.95 m), the upstairs floors and the veranda (3.0 m). Roofs stop shots only, so a gap in the caps is a way into a sealed house. After any change to its buildings, run a walk-jump-and-vault check over the whole map before pushing.
- **On Area 51, nothing more than 3.15 m over the floor under it can be stood on, and every flat roof is a floor.** The caps are Alpine's, made at the end of the build, but measured from the floor under each box: the highest walked-on (`walk`) top under it (a roof, for what stands on a roof), or the ground. A capped top that is narrow (0.8 m or less across: a lamp, a downpipe's head, a wall unit) and alone (not a strip of a wider top at its height, as a truck canopy's collision columns are) becomes a rail instead of a 12 m wall, so nothing invisible stands in the air beside a roof (he could not jump off the roofs or over their AC units when the caps were counted from the ground, 24 Nov). Everything a player can reach must jump, vault and climb as it looks (his rule, 24 Nov): test every prop from every side and every roof edge with the game's own movement before reporting. The balcony, stair and booth rails are not capped, so they can be jumped and vaulted over; instead the map wraps `moveCapsule` and slides a player off any `.rail` top, because the game's floor test takes any top within a step under the feet as floor, so anything a jump clears can also be landed on. After any change to its buildings, run `__SALTLINE_MAPS.area51._debug.reach()` in the console: it walks and jumps the whole map, and its list of faults must be empty. The map draws its own sunbeams and motes (as Maram does), lays one `interiorBoxes` box over the whole compound for the haze, and zeroes the game's rain at load (it otherwise eases out over 20 s). Its ground marks are linear vertex colours: a dark stain needs values near 0.02. Its vehicles are downloaded models, prepared once by `node scripts/area51-models.mjs <folder>` into `web/maps/area51/models/` (the `.glb` files are never committed): the map loads them before the build so their collision boxes (columns of the model's own shape) are there for the caps, the walk grid and the beams, places them only by quarter turns (the boxes are square to the world), and builds its old boxy vehicle in a model's place if that model does not load. Props (crates, pallets, drums, tanks, tables, AC units) are models drawn in the place of a box the map already builds: the box stays the collision, so swapping a prop's model changes no movement check. Keep the dev server stopped, or restart it, when converting many models: its file watcher crashes on a texture rewritten under it. Its canopy sheets, its dock sheets, its camo net and its windsock are simulated cloth (`makeCloths`, `makeWindsock`: Verlet points and joins, moved every frame on High and Ultra, every other on Medium, hung once on Low); what stops shots stays where the cloth hangs at rest. The search radar's head turns: a part that turns is built in its own builder round its pivot and listed in `spinners`, and its collision is one box over the whole sweep. On its two stair flights the eye rides a ramp through the middles of the treads (`smoothEye`, wrapped round `G.render.frame`): the game lifts feet and eye a whole 25 cm tread in one frame. The eye is moved for the drawing and put back after it, so the game always sees its own camera; a new flight needs its rectangle and ramp there. Its drums are the game's own explosive barrels (`level.explosives`, as the Colosseum's): the game makes them a few seconds after the level, so a check run straight after load finds none. It draws light shafts only under the camo net: under an open-sided roof at noon they read as white smoke. Concrete lying on the ground (the hangars' apron, the gate's slab) is listed in `GROUND_SLABS` and the yard is cut out under it: the yard is drawn with a polygon offset, and from far off it came through a slab laid over it. The ground's colour is one setting, `LOOK` in `makeMaterials` (how much of each photograph's own colour is kept, and a gain): `[1, 1, 1, 1]` gives the orange mud and pink rock back. The yard's wheel tracks and darker gravel are one picture painted from `TRACKS` and laid over the whole yard. Outside the fence the ground is 1 m squares in the world patch, 2 m to 108 m, 4 m to 220 m and 20 m beyond; `edgeH` makes a finer grid's edge follow the coarser one's, so a slope opens no crack, and the road's banks widen far out, where a 2 m bank on 4 m squares became a saw. The barracks and the east wing have steel stairs up their walls to their roofs (`ROOF_STAIRS`); every lower flat roof beside them (annex, comm block, both bunkers: `roof: true`) is walked on too, to drop onto. Treads, roofs and wall heads are marked `walk` and not capped, and `reach()` allows them (its faults are measured from each top's floor as well). Parapets are ledges: stood on, walked along, jumped or vaulted over. Where a low roof meets a taller block's wall there is no parapet (a 30 cm ledge against a wall leaves no room for a 64 cm body); the roof's felt is turned up the wall. Every walked-on ledge stands over the game's 42 cm step (the bunkers' are 53 cm): a lower one lifted a player brushing past onto it in one frame. The porches' slab roofs, the picnic canopy, the camo net and the dock's sails can be dropped onto from above: what holds a player there is marked `walk` and follows the cloth in steps. The comm block's tower is boxed bay by bay to 12 m (its braced faces leave no gap a body fits). What stands on a walked-on roof stops players and is measured from the roof; the roof cover pieces (`coverRTU`, `coverCrates`, `coverTanks`, `coverPallets`, `coverGen`) are 1.3 to 1.6 m: a crouching player's head (1.15 m) hides behind one, and the vault (1.65 m) still climbs it. The annex has three crate heaps up to the barracks' coping (walked, like treads), and the open yard south of the barracks has seven heaps of the same kind. Nothing is hung on a wall where a stair runs (`stairBusy`). The rail guard pushes a player off a rail by their whole width and never into a box. Falls cost more here than in the game (`FALL` in the map: none under 4.5 m, 80 at 8.55 m, a jump over a roof's parapet; the map tops up the game's own `(speed - 16) x 5` through `G.player.damage`), and only on this map. The stores (shot 119) are three 40 ft containers on the back of a 55 cm dock cast in slabs, its ramp eleven 5 cm steps for players under a drawn slope, with its own `smoothEye` ramp; the flatbed Ural backs onto its east end. Its puddles (`makePuddles`) are on layer 2, which the camera sees and the game's mirror pass does not: a puddle drawn into the mirror picture it reads is a feedback loop. They mirror the sky at every quality; the mirror pass itself (the world drawn a second time: it roughly doubled the frame time at High, measured on a busy machine; `perf-hooks` turns it off at High for the harbour, and `MIRROR_HIGH = 0` in the map does the same here) runs on High at half size and on Ultra, and only while a puddle is in view within 16 m (High) or 30 m (Ultra), eased in and out. High and Ultra must look it (he saw no difference, 24 Nov): the map keeps `mats.q` (0 low to 3 ultra) in step with the game's setting every frame and its shaders branch on it. High adds the yard's broken repeat, haze on the far desert and sunlight through cloth and leaves (`mats.backlit`); Ultra adds a finer grain of the ground's own picture and relief within 16 m, anisotropic filtering at the card's most (16; below Ultra each texture keeps its own), and the ground's loose stuff (`makeClutter`: about 10,000 rounded stones of 3 to 14 cm and 1,000 tufts of dry grass, no collision, made after the puddles so it keeps out of them, a third of it on High). Never put a world object on layer 1: that is the gun's pass, drawn over everything (the stones floated over a generator there), and the headless renders hide it, so check with the gun's view on. The sky photograph is turned a deeper blue above the hills (`PANO`, the visible sky only; the lighting's copy is left). A puddle is laid only where all of it lies on open ground (its rim is checked, not just its middle). A new model needs its credit in the README. After a new game export, watch the console for `[area51]` warnings: the weathering, the corrugation fade and the desert's broken-up repeat each look for a line in the game's shaders.
- **Maram's collision is generated.** `web/maps/maram/world.json` comes from `node scripts/maram-build.mjs` (pass a `.glb` to take in a new model); never edit it by hand. The build fails if a spawn, an ammo pile or the intro camera path is wrong, and prints what its walk-and-jump robot reached. The map replaces the game's raycast, moveCapsule and groundHeight with the same code over a grid (it has about 40,000 boxes) and checks them against the game's own on load; after a new game export, watch the console for `[maram] the grid physics disagreed`.
- **The game reads `volSigma`, `volFarHaze` and `volMaxDist` from `render.tune` only when the renderer starts.** A map that sets them changes nothing (Alpine's `volSigma` never took effect); `volSunScale`, `volAmbient` and the covered-box density (`volInterior…`) are read every frame. That is why Maram draws its own sunbeams. Maram also borrows Alpine's texture folder (`web/maps/alpine/tex/`) for its surface detail: renaming a texture there leaves Maram plain.
- **`interiorBoxes` is also the sound's indoors.** The game's audio counts a listener inside any entry as indoors and sends every shot, step and impact through its shed reverb (the outdoor one at a tenth). Maram and Area 51 put one whole-map box there for the haze only, so every match on them echoed like a shed until each map hid that box from `G.audio.update` (`outdoorSound`, called from the map's update). A new map that uses a box for the light must do the same. Read the live value with `G.audio.debug().interior`: `G.audio.interior` is a copy taken at start and always reads 0.
- **Move the camera before `G.render.frame`, never in a pre-pass.** The frame copies the camera into the one that draws the gun and arms first, then runs the pre-passes, so a camera moved in a pre-pass leaves the gun behind (Maram's smoothed eye made the gun jump on every stair until it wrapped `G.render.frame` instead).
- **Grenades fly in fixed steps of 1/120 s** (gun hook 24), and `web/fragpath.js` flies the cooked grenade's path through a copy of those steps (`stepFrags`, with hook 22's floor ray): change one and change the other, or the drawn path lies. Measured on Alpine: where the grenade goes off is within 5 cm of the drawn end. A grenade's floor is a ray down, never `groundHeight`, which counts player-only boxes (Alpine's 12 m caps), and that ray starts at most 60 cm up and never above a ceiling (it looks up first), or a grenade near a ceiling lands on the floor above.
- **Deathmatch colours are unique per room.** The rows are in `net.js` (the last block); the colour is the game's (`window.__SALTLINE_COLOR`, import patch 11). On a clash, whoever was in the room first keeps it (`room.earlier(peer)`: the peers already there when this page first joined).
- **Typed radio is gone.** `scripts/import.mjs` (10) takes out the T key, its line, its hint, its key in Controls and the lines sent and read aloud; `net.js` offers no `tts`. Voice chat (V) is untouched. A new export keeps it out only while those anchors still match.
- **Vaulting is `web/vault.js`**, called from hooks in `scripts/gun-hooks.mjs` (17) at the game's jump. It clears tops from 45 cm up to 1.65 m above the feet, under what a jump reaches (1.69 m with the step), or as high as the map's `level.vaultMax` (Alpine: 1.95 m, safe there only because of the caps above). Up to 1.2 m (or the map's `level.vaultClimb`; Area 51: 0.85 m, so a jump at its compressor lands on it), or across anything thinner than half a metre, it goes over; higher and deeper (a block, a crate) it climbs onto the top. It tries straight ahead and square on to the face, each a little to either side, so a window is found without lining up on it; boxes marked `noVault` are never vaulted (Alpine's bushes had it; they are no longer solid at all). A map that sets `level.vaultSteps` (Area 51 only) lets a vault start beside a step: going over something (never onto it), until the hands reach its top the path ignores boxes within a step (42 cm) of the feet, so a vault over a stair's rail is not refused by the next tread. Never for a climb onto, which would turn a jump up a stair into a climb onto the steps above; and not on Alpine or Maram, where it would add vaults nobody has played. The motion is one curve through a few moments (start, hands, edge, over, out) that keeps the player's speed. It checks the whole path against the boxes near the player first; `__SALTLINE_VAULT.why()` in the console says why the last try was refused, `.last()` how the last vault went, `.test(G, x, y, z, yaw)` what a vault from a spot would do. The body is the soldier rig's own pose with a few extra inputs (a hand on the ledge, knees tucked, hips low, a lean): your hands are the knife's first-person arm (a mirrored copy for the left), the gun dips in the weapon's own holster pose, and other players get `vt` in the presence.
- **A peek is drawn where it is.** Leaning (Q/E) moves the eye up to 50 cm to the side and 20 cm down; the presence carries the offset (`lo`), and other players' games lean the soldier from the hips (`leanK`) so his head is where that eye is, his feet moving at most 25 cm to make up the rest, with the hitboxes following (gun hooks, section 18). Measured: head within 2 cm of the eye, feet about 17 cm. Anything that changes how far the eye leans or how the body tilts must keep the two in step.
- **A reload goes back into the match.** On joining a match `net.js` keeps the room, mode and team in `sessionStorage` (`saltline.resume`, this tab only, fresh for ten minutes) and a reload joins the same room again; going back to the menus or Leave room forgets it.
- **A private room's map can change.** Its lobby sends `{t:'map'}` over the room's socket; the Room stores it and tells everyone, and every page reloads into the new map at `/r/<code>`. Public rooms keep their map, because quick play finds them by map.
- **Kills and deaths are kept by the score hooks** (`scripts/score-hooks.mjs`, run last by the import). Event numbers (shots, hits, deaths, blasts, grenades) grow with the clock, never from 1, so a reloaded page's are newer than anything it sent before. Each game remembers for a minute what it saw from a player who went (`mp.seen`) and carries on from there when the same player id comes back, so a death in their first message still counts. The room never announces a reconnect from the same tab as a join (`src/worker.js`). `net.js` keeps the tab's player id across reloads (`saltline.peer`, sessionStorage; a duplicated tab asks the other tabs over a BroadcastChannel and takes a new one), and the game keeps this round's counts for the tab (`saltline.score`) and gives them back only to the same player id in the same room and round. Counts remember their round (`stats.rd`) and are cleared on joining a later one. In Team deathmatch each player sends counts for both sides (`kt`); kills made for a side before changing stay with it as a "(moved to …)" row. Ctrl+R does nothing in the middle of play. Run `node scripts/score-check.mjs` against `npm run dev` after any change to scores, rounds, the room or the presence: it plays five rounds with a real tab and fails on any wrong count or any error the page throws.
- **Check guns with two players.** One browser cannot be shot. Two tabs on `npm run dev`, both in Deathmatch: shoot the other, read the kill feed and the card shown when down, come back, walk to the gun you dropped and hold **G**, then open the bag with **B**.
- **The bag and the guns on the ground are `web/bag.js`**, with its hooks in `scripts/bag-hooks.mjs` (run last by the import) and the list kept by the Room (`src/worker.js`: `drop`, `take`, `drops`; the first take of an item wins, items last 60 s, pruned whenever the list is read, cleared on a map change). Only in a live match. A player carries two things (`slots`, a gun and the knife at first); spare rounds belong to the kind of gun (`pool`), so two rifles share one spare and the game's one magazine per kind is filled from the slot in use (`load`/`save`; two of a kind switch with the weapon's own holster-and-draw, `weapon.redraw`, hook 2). Going down drops every gun (never the knife) through the same floor ray as grenades; a gun leaving a player takes its magazine and its share of the spare (all of it, or half when another of its kind stays). A death in the middle of a swap settles when the room answers: whatever ended up the player's is dropped where they fell. The bag is kept for this tab in `sessionStorage` (`saltline.bag`: room, player id, round, mode) so a reload neither refills it nor loses a picked-up gun; going down or leaving forgets it. B no longer chooses the next gun: that is the card shown when down. Run `node scripts/drops-check.mjs` against `npm run dev` after any change to the bag, the guns, deaths, rounds or the Room: it drives real tabs with real key presses (every combination of held, other and ground, two tabs racing for one gun, a death mid-swap, a reload, a new round, touch) and fails if any round is made or lost.
- **The Worker name stays `cod`.** It was renamed from `saltline` in the dashboard, which carried over the custom domain and Durable Objects (their namespaces are still called `saltline_Room` / `saltline_Matchmaker`). Changing `name` in `wrangler.jsonc` alone makes a new, empty Worker instead; rename in the dashboard first.
- **Durable Object classes change only through a new migration tag** in `wrangler.jsonc` (`v2` today). Never edit or delete an existing tag.
- **`master` is production.** Anything merged there goes live in about a minute. Run `npm test` against `npm run dev` before pushing. It is a protocol smoke test that needs a running server, so CI does not run it.
- **The repo is public.** Secrets go in `wrangler secret put` (runtime) or `.dev.vars` (local, gitignored), never in `wrangler.jsonc`.
